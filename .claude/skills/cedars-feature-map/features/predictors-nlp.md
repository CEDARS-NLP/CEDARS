# Predictors, LLM client and NLP

Last verified: working tree on 2026-10-15 (source; working tree/not committed; local tests only)

This area covers API-only predictor configs and legacy EventConfigs, the shared LiteLLM client, and spaCy keyword NLP. The evaluation list's "Run a search query" mode and its `NlpQueriesSection` were removed; session step 1's "Run on all patients" is now the only UI path to keyword NLP, without an event/provider/model. The engine now enforces AND, grouped Boolean expressions, phrases and sentence-scoped exclusions with bounded expansion, using existing dependencies and models with no migration. Admins mutate; every role can read. Overall: reachable keyword NLP is beta pending current live/Postgres verification; predictors/EventConfigs remain api-only, PINES remains stub, and LLM client grades are unchanged. Source reviewed on 2026-10-15 in the working tree/not committed; 2026-10-05 live observations remain historical, not proof of deployment/current behavior.

## How to get to it (user POV)

1. Predictor configs, legacy EventConfigs and NLP query CRUD are API-only. For keyword NLP, open sidebar "Evaluation", start or open a session, and use step 1's "Run on all patients" (see [evaluation-setup.md](evaluation-setup.md)).
2. LLM client: an admin sets "LLM provider", model and API base on the project (create page or Overview settings; see [projects.md](projects.md)). Every evaluation sample run, query suggestion and full pipeline then goes through `llm/client.py`.
3. Session NLP: choose "Test an LLM filter first", then "New session". Step 1 is the query editor, before event definition (see [evaluation-setup.md](evaluation-setup.md)). Saving folds local rows into one expression. Sample search uses that expression without activating a project query; "Run on all patients" activates one query and runs keyword NLP with no model (see [evaluation-run.md](evaluation-run.md)).

## Gotchas

- **Boolean exclusion is not clinical negation.** `!term`/`!(group)` evaluates within the sentence and OR branch; NegEx remains a separate clinical-negation filter. AND/grouping/phrase defects are fixed with bounded expansion (`engine.py:113-199`, `tests/test_nlp.py::test_grouped_exclusions_are_sentence_scoped`). Very large valid expressions can reject by design rather than expand without bounds.
- **Negation catches only cues that come first.** No deployment sets `CEDARS_SPACY_MODEL` (`config.py:51` defaults to `""`), so every stack uses `spacy.blank("en")` with a sentencizer (`engine.py:31-66`), and negation is the 5-token look-back. "DVT was ruled out." comes out as target and not negated. The cue list holds single words only (`engine.py:21-25`).
- **NLP run skips processed notes.** `_process_notes_into_sentences` handles only non-deleted notes with no sentences (`nlp/service.py:296-306`). New or edited project queries require reprocessing to change old results. There is only one active project query; session save normalization is a separate operation (`query_expression.py:6-35`).
- **Reprocess still destroys review work, now with confirmation.** Impact preview includes annotations, predictions and sentences; confirmation compares all three counts, and busy/recent-lock guards reject before session run-all activates its query (`evaluation/service.py:277-307`). `clear_sentences` deletes those records and resets patient review metadata (`nlp/service.py:632-670`), including evaluation annotations and reviewer decisions. Destructive reprocess remains synchronous, and no audit row is added by this change.
- **`pred-crud` has a known security defect.** Details are tracked privately, not in this public repo.
- **Evaluation never uses a predictor config.** Sessions always classify with the project's LLM settings (`evaluation/service.py:530`, `:638`, `:700` → `classify_patient`). There is no predictor picker, so PINES or a predictor config cannot be evaluated through the UI. Only the API-only bulk predictions read `/predictors`.
- **PINES cannot work in v2.** `infra/cedars-v2/README.md:176` calls PINES "deferred/optional in v2", but CLAUDE.md's deferred list does not include it. The map grades `pred-pines` `stub`, not `deferred`, because the code ships and is reachable through the API.
  - `/predict` returns `{"prediction": ..., "model": ...}` (`PINES/pines.py:90`). The client reads `score` and `label` and defaults both, so it always gets label 0 and score 1.0 (`predictors/pines.py:35-40`).
  - The batch body `{"texts": [...]}` does not match the service's `list[Note]` (`PINES/pines.py:95`). That gives 422, and the client falls back to single calls (`pines.py:67-69`).
  - The default URL `http://localhost:8000` does not match the service port 8036 (`PINES/pines.py:110-113`).
  - `Settings.pines_api_url` (`config.py:39-40`) is never read.
  - No v2 compose file or Terraform defines a PINES service.
- **`LLMPredictor` still invents negatives.** A `{}` or partial reply defaults to `event_detected=False` and `confidence=0.5`, giving label 0 and score 0.5 (`predictors/llm.py:163-168`). An unparseable reply gives label 0 and score 0.0 (`:155-161`). cef61132 fixed this class of bug in the classifier (`pipeline/classifier.py:121-129`) but not here. `response_format` is never sent on this path.
- **`pred-test` has a known security defect.** Details are tracked privately, not in this public repo.
- **No provider allow-list in v2.** Any string up to 50 chars is accepted (`projects/schemas.py:9`). Unknown providers reach LiteLLM with a bare model name (`client.py:99`). CLAUDE.md's "Provider whitelist" describes v1.
- **The classifier truthiness is loose.** `bool(data.get("event_detected"))` treats the string `"false"` as True (`pipeline/classifier.py:131`).
- **Two job-status contracts remain.** Fresh NLP uses BackgroundJob `/nlp/job/status`; synchronous reprocess uses legacy NlpJob `/nlp/job`. The reachable component polls both (`NlpQueriesSection.tsx:69-88`). Session run-all returns their existing union and recognizes immediate completion (`evaluation/router.py:185-198`, `SearchQueriesSection.tsx:435-445`).
- **The ARQ fallback hides a missing worker.** When `arq:queue:health-check` is absent, NLP and prediction jobs run in-process with `asyncio.create_task` in the web container (`nlp/service.py:114-153`, `annotations/prediction_service.py:196-232`). They die if the container restarts.
- **Synthetic EventConfigs.** Every evaluation commit adds a committed EventConfig, because `PipelineRun.event_config_id` is NOT NULL (`evaluation/service.py:1127-1156`). The legacy `/pipeline/events` list therefore grows with each commit, and the copied project `llm_api_key` is stored on it (`:1151`). `EventConfigResponse` does not return that key (`pipeline/schemas.py:36-50`).
- **The fake LLM only knows the evaluation prompts.** It parses `--- Excerpt from note ...` blocks (`.claude/skills/verify-cedars/stack/fake_llm.py:39-42`, `:65-66`). `LLMPredictor` prompts never match, so every `pred-test` and bulk prediction against the fake comes back negative with confidence 0.85, i.e. score 0.15 (`:80-86`).
