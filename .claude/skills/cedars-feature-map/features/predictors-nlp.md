## How to get to it (user POV)

1. No page manages predictor configs, NLP queries or EventConfigs. Use the API.
2. LLM client: an admin sets "LLM provider", model and API base on the project (create page or Overview settings; see [projects.md](projects.md)). Every evaluation sample run, query suggestion and full pipeline then goes through `llm/client.py`.
3. NLP engine: new Evaluation session -> "Search queries" -> "Save queries" -> optional "Preview sample", then keyword-only full run or optional LLM branch. Version 2 uses `query_expression.py::select_note_sentences` for both scopes. Existing version-1 sessions keep their legacy search (`evaluation/service.py`).

## Gotchas

- **Version-2 semantics and limits:** bounded grammar (8192 expression characters, 512 syntax tokens, depth 32; REST maximum 50 rows/5000 characters per row). Include rows OR together; exclude rows veto sentences, not whole notes/patients. Overlapping includes do not duplicate retained sentences. At least one retained positive hit is required; invalid/exclude-only saves return 422. Active syntax-version-2 NLP execution uses the shared selector (`nlp/service.py:332`). PostgreSQL concurrency and live parity remain pending.
- **Model snapshots, not predictor picking:** version-2 prompt revisions freeze project provider/model/API base, event fields, template/version and non-secret settings. Runtime credentials are resolved from the project and guarded against provider/endpoint changes (`query_first.py:277`); no API key is stored on prompt revisions. A changed model requires a new prompt save for new work. Existing revisions retain the old model. Keyword-only runs never read an active predictor for classification.
- **Legacy parser drops AND, phrases and parentheses.** The following are October 5 reproductions for version-1 evaluation/standalone legacy parsing, not the new grammar (`evaluation/service.py:292-297`, legacy worker path):
  - AND is not enforced: any one positive condition makes a sentence a target (`engine.py:201-218`), so `troponin AND elevated` matches "Troponin was drawn.";
  - multi-word terms never match, because each term becomes one `LOWER` token pattern (`engine.py:157`). `pulmonary embolism` finds nothing;
  - parentheses are stripped only at the ends of the string and of each OR group (`engine.py:111`, `:118`). The docstring's own example, `(DVT OR embolus) AND !suspected` (`:99`), parses to the term `embolus)`, so "Large embolus seen." does not match;
  - `tests/test_nlp.py::TestQueryParser::test_parenthesized_groups` only asserts `len >= 1`.
- **Negation catches only cues that come first.** No deployment sets `CEDARS_SPACY_MODEL` (`config.py:51` defaults to `""`), so every stack uses `spacy.blank("en")` with a sentencizer (`engine.py:31-66`), and negation is the 5-token look-back. "DVT was ruled out." comes out as target and not negated. The cue list holds single words only (`engine.py:21-25`).
- **NLP run skips processed notes.** `_process_notes_into_sentences` handles only notes with no sentences (`nlp/service.py:234-246`). New or edited queries change nothing until `/reprocess`. All active queries are merged into one OR list (`:229-232`).
- **Reprocess destroys review work.** `clear_sentences` runs `DELETE FROM annotations WHERE project_id = :pid` (`nlp/service.py:403-406`). That deletes evaluation-pipeline annotations and reviewer decisions too, with no confirmation and no audit row. It runs synchronously inside the HTTP request (`nlp/router.py:151-160`).
- **`pred-crud` has a known security defect.** Details are tracked privately, not in this public repo.
- **Evaluation has no predictor picker.** Version 2 classifies with a saved project-model prompt revision (`query_first.py::runtime_config`); version 1 reads project settings at execution (`evaluation/service.py`). PINES/configured predictors are not selectable for session evaluation. Bulk predictions read `/predictors`; keyword-only full runs make zero classifier calls.
- **PINES cannot work in v2.** `infra/cedars-v2/README.md:176` calls PINES "deferred/optional in v2", but CLAUDE.md's deferred list does not include it. The map grades `pred-pines` `stub`, not `deferred`, because the code ships and is reachable through the API.
  - `/predict` returns `{"prediction": ..., "model": ...}` (`PINES/pines.py:90`). The client reads `score` and `label` and defaults both, so it always gets label 0 and score 1.0 (`predictors/pines.py:35-40`).
  - The batch body `{"texts": [...]}` does not match the service's `list[Note]` (`PINES/pines.py:95`). That gives 422, and the client falls back to single calls (`pines.py:67-69`).
  - The default URL `http://localhost:8000` does not match the service port 8036 (`PINES/pines.py:110-113`).
  - `Settings.pines_api_url` (`config.py:39-40`) is never read.
  - No v2 compose file or Terraform defines a PINES service.
- **`LLMPredictor` still invents negatives.** A `{}` or partial reply defaults to `event_detected=False` and `confidence=0.5`, giving label 0 and score 0.5 (`predictors/llm.py:163-168`). An unparseable reply gives label 0 and score 0.0 (`:155-161`). cef61132 fixed this class of bug in the classifier (`pipeline/classifier.py:121-129`) but not here. `response_format` is never sent on this path.
- **`pred-test` has a known security defect.** Details are tracked privately, not in this public repo.
- **No provider allow-list in v2.** Any string up to 50 chars is accepted (`projects/schemas.py:9`). Unknown providers reach LiteLLM with a bare model name (`client.py:99`). CLAUDE.md's "Provider whitelist" describes v1.
- **The classifier truthiness is loose.** `bool(data.get("event_detected"))` treats the string `"false"` as True (`pipeline/classifier.py:131`).
- **Two job-status endpoints.** `/nlp/run` writes a `BackgroundJob` (`/nlp/job/status`). Reprocess writes a legacy `NlpJob` (`/nlp/job`, `nlp/service.py:286`). The orphaned UI read only `/nlp/job` (`NlpQueriesSection.tsx:40`).
- **The ARQ fallback hides a missing worker.** When `arq:queue:health-check` is absent, NLP and prediction jobs run in-process with `asyncio.create_task` in the web container (`nlp/service.py:114-153`, `annotations/prediction_service.py:196-232`). They die if the container restarts.
- **Synthetic EventConfigs.** Full attempts/legacy commits add a bridge because `PipelineRun.event_config_id` is NOT NULL. Version 2 stores no credential on its bridge (`query_first.py:302`); keyword-only uses empty provider/model fields. The legacy commit bridge copied the project's `llm_api_key` (`evaluation/service.py:1151`); its response excludes it. Do not generalize that credential-copy claim to version 2.
- **The fake LLM only knows the evaluation prompts.** It parses `--- Excerpt from note ...` blocks (`.claude/skills/verify-cedars/stack/fake_llm.py:39-42`, `:65-66`). `LLMPredictor` prompts never match, so every `pred-test` and bulk prediction against the fake comes back negative with confidence 0.85, i.e. score 0.15 (`:80-86`).
